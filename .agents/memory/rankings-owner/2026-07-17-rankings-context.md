# Rankings context

## 2026-07-17 — LIVE FEED LANDED (real ongoing-tournament data)
Live bar no longer placeholder. Now driven by real in-progress tournament data. Key change: **detection is by a `live` flag, NOT anniversary date-projection anymore.**
- **Data path (zero new API calls needed):** ETL already archives ongoing tournaments as `{status:'ongoing', players:{id→deepest round SO FAR}}` and pivots them by playerId into each top-100 player's `points_distribution`. So the in-progress event is ALREADY in `static/data/{tour}.json` after a refresh — it was just indistinguishable from a finished bar.
- **The flag:** added `live?: boolean` to `TournamentResult` (`types.ts`). `etl.ts buildDistribution` sets `live:true` when the source archive `status==='ongoing'`. `points_earned`/`result` = round reached so far (a FLOOR, e.g. R16 of a 250 = 25pts; R32 of a 250 = 0pts → tiny 2px bar, honest).

New: `liveResult = visibleResults.find(r=>r.live)`; `defendingResult` = same `event_name`, non-live (last yr's edition, matched by name); `mainResults = visibleResults.filter(r=>!r.live)` feeds all main-chart loops so the live entry does NOT double-render as a normal bar. Live pane uses real `liveResult.result`/`points_earned`. Tooltip (`liveTip`) two-pane Live|Defending; **Defending pane is now optional** (`{#if tooltip.defending}` — many small-250 live players weren't in last yr's edition → single-pane Live card, min-w-48).
- **Flag flipped ON:** `SHOW_LIVE_POINTS = true` (`flags.ts`). `SIM_NOW = null` now (real clock).
